# Duffy Review

เว็บรีวิวเกม — **frontend** (HTML/CSS/JS) deploy บน Vercel, **backend** (Node.js + Express) deploy บน Render

```
frontend/   หน้าเว็บ (index.html, news.html, profile.html, site.css, login.html, register.html, auth.css, admin.html, favicon.svg, config.js, vercel.json)
backend/    REST API (server.js, auth.js, members.js, news.js, store.js, data/games.json)
render.yaml ตั้งค่า Render
```

## API
| Endpoint | ใช้ทำอะไร |
|---|---|
| `GET /api/games?q=&cat=&age=&sort=` | ค้นหา/กรอง (`sort` = new, pop, score) |
| `GET /api/games/:id` | รายละเอียดเกม |
| `GET /api/top` | Top 10 คะแนนสูงสุด |
| `GET /api/health` | เช็กสถานะ |

## รันในเครื่อง
```bash
cd backend && npm install && npm run dev      # http://localhost:3000
cd frontend && npx serve .                     # เปิดหน้าเว็บ (config.js จะชี้ localhost:3000 อัตโนมัติ)
```

## Deploy
1. **Push ขึ้น GitHub** ทั้งโฟลเดอร์นี้เป็น repo เดียว
2. **Render (backend)**: New → Web Service → เลือก repo → ตั้ง Root Directory = `backend`, Build = `npm install`, Start = `npm start` (หรือใช้ Blueprint จาก `render.yaml`) → ได้ URL เช่น `https://duffy-review-api.onrender.com`
3. **แก้ `frontend/config.js`** ใส่ URL ของ Render แล้ว commit/push
4. **Vercel (frontend)**: Add New Project → เลือก repo → ตั้ง Root Directory = `frontend`, Framework = Other (ไม่ต้อง build) → Deploy
5. **CORS**: กลับไป Render → Environment ใส่ `CORS_ORIGIN` = โดเมน Vercel เช่น `https://duffy-review.vercel.app` แล้ว redeploy

> แพ็กเกจฟรีของ Render จะหลับเมื่อไม่มีคนใช้ การเปิดเว็บครั้งแรกอาจรอประมาณ 30–50 วินาที

## เปลี่ยนข้อมูลรีวิว
แก้ไฟล์ `backend/data/games.json` (ตอนนี้เป็นข้อมูลตัวอย่าง) ภายหลังเปลี่ยนไปใช้ฐานข้อมูลจริงได้ เช่น PostgreSQL บน Render

## แก้ไขเกม / ใส่รูป / ความคิดเห็น
- **ชื่อเกมและเนื้อหารีวิว**: แก้ใน `backend/data/games.json` (`title`, `category`, `age`, `score`, `desc`, `review`, `pros`, `cons`, `platforms`)
- **รูปปก**: อัปโหลดรูปไว้ที่ `frontend/images/` แล้วใส่ `"image": "images/ชื่อไฟล์.jpg"` (หรือใส่ลิงก์รูป https://... ก็ได้) แนะนำสัดส่วน 16:9 เช่น 800×450 ขนาดไม่เกิน ~300KB
- **ความคิดเห็น**: เก็บที่ `backend/data/comments.json` ตอนรัน (ข้อมูลบน Render แพ็กเกจฟรีจะหายเมื่อ deploy ใหม่/รีสตาร์ต ถ้าจะใช้จริงจังควรย้ายไปฐานข้อมูล)
- **ลบคอมเมนต์สแปม**: ตั้ง `ADMIN_TOKEN` บน Render แล้วเรียก `DELETE /api/comments/:id` พร้อม header `x-admin-token`

## ยอดเข้าชม (👁)
นับจริงเมื่อมีคนเปิดหน้ารีวิวเกม (1 คน/1 เกม/30 นาที นับครั้งเดียว) และหน้าเว็บอัปเดตตัวเลขอัตโนมัติทุก 10 วินาที เก็บที่ `views.json` (บน Render ฟรีจะรีเซ็ตเมื่อ deploy ใหม่) ถ้าอยากตั้งยอดเริ่มต้น ให้แก้ฟิลด์ `views` ใน `games.json`

## ยอดเข้าชม (View counter)
- ทุกครั้งที่มีคนเปิดหน้ารีวิว หน้าเว็บจะเรียก `POST /api/games/:id/view` ยอดใหม่แสดงทันที และรายการหน้าแรกรีเฟรชยอดเองทุก 20 วินาที
- คนเดิมเปิดเกมเดิมซ้ำภายใน 60 วินาทีนับครั้งเดียว (ปรับได้ด้วย `VIEW_COOLDOWN_SEC` บน Render)
- ยอดเริ่มจาก 0 (ค่า `views` ใน games.json คือยอดตั้งต้น ใส่เลขเพิ่มได้ถ้าต้องการ)

## เก็บข้อมูลถาวร (แนะนำ)
ตั้ง Environment Variable `DATABASE_URL` บน Render เป็น connection string ของ PostgreSQL (เช่น Neon, Supabase หรือ Render Postgres) ระบบจะสร้างตารางเองและเก็บยอดวิว+ความคิดเห็นถาวร ถ้าไม่ตั้ง จะเก็บเป็นไฟล์ซึ่งหายเมื่อ deploy ใหม่/รีสตาร์ตบน Render ฟรี

## ฐานข้อมูล SQL (PostgreSQL)
ไฟล์ใน `backend/db/postgres/` (และ `backend/db/mysql/` สำหรับ MySQL): `schema.sql` (สร้างตาราง games, views, comments), `seed.sql` (เกมตัวอย่าง 12 เกม), `examples.sql` (คำสั่ง INSERT/UPDATE/DELETE ที่ใช้บ่อย)
- ตั้ง `DATABASE_URL` บน Render แล้วเซิร์ฟเวอร์จะรัน schema + ใส่เกมตัวอย่างให้เองตอนเริ่ม (ถ้าตาราง games ว่าง)
- จะรันเองก็ได้: เปิด SQL Editor ของ Neon/Supabase วาง `schema.sql` แล้ว `seed.sql`
- แก้เกมผ่าน SQL แล้วหน้าเว็บอัปเดตเองภายใน ~1 นาที

## ใช้ MySQL + phpMyAdmin แทน PostgreSQL
- ตั้ง `DATABASE_URL` เป็น `mysql://USER:PASSWORD@HOST:3306/DBNAME` (รหัสผ่านที่มี @ : / # ต้อง URL-encode เช่น `@` = `%40`) ระบบจะเลือกใช้ MySQL เองจากคำว่า `mysql://`
- ถ้าผู้ให้บริการบังคับ SSL ให้เพิ่ม `DATABASE_SSL=true`
- สร้างตารางผ่าน phpMyAdmin: เลือกฐานข้อมูล > แท็บ Import (หรือ SQL) > `backend/db/mysql/schema.sql` แล้ว `seed.sql` — หรือไม่ต้องทำ เซิร์ฟเวอร์สร้างให้เองตอนเริ่ม
- ฐานข้อมูลต้องรับการเชื่อมต่อจากภายนอก (Remote MySQL) เพราะ backend อยู่บน Render

## หมวดหมู่และเรตอายุในเมนู
สร้างอัตโนมัติจากข้อมูลเกม (`/api/meta`) เพิ่มเกมที่มีหมวดใหม่แล้วปุ่มหมวดนั้นจะโผล่เอง ไม่ต้องแก้หน้าเว็บ

## เปลี่ยนข้อมูลเกมชุดใหม่ในฐานข้อมูลที่ใช้งานอยู่
ระบบใส่ข้อมูลจาก `games.json` ให้อัตโนมัติเฉพาะตอนตาราง games ว่าง ถ้าฐานข้อมูลมีเกมเดิมอยู่แล้ว ให้รัน `db/postgres/replace_games.sql` หรือ `db/mysql/replace_games.sql` (ลบเกม ยอดวิว และคอมเมนต์เดิมทั้งหมด)

## ให้ดาว -> คะแนนรวม
ผู้อ่านกดดาว 1-5 ในหน้ารีวิว (1 เบราว์เซอร์ต่อ 1 เกม เปลี่ยนดาวได้) เก็บในตาราง `ratings`
คะแนนรวม = (คะแนนทีมงาน x 10 + ดาวทุกดวง x 2) / (10 + จำนวนโหวต) ปรับน้ำหนัก 10 ได้ด้วย `SCORE_PRIOR_WEIGHT` บน Render
เปิด `/api/health` จะเห็น version, storage และจำนวนเกม ใช้เช็กว่า deploy เวอร์ชันล่าสุดแล้ว

## ระบบผู้ดูแล (Admin) — เพิ่ม/แก้ไข/ลบรีวิว + Login/Logout
เปิด `https://โดเมนของคุณ/admin` (หรือ `admin.html`) โดยพิมพ์เอง หน้าเว็บไม่มีลิงก์ให้คนทั่วไปเห็น (ผู้ดูแลที่ล็อกอินแล้วจะเห็นปุ่ม "หน้าผู้ดูแล" มุมขวาบนของหน้าเว็บ)
- **เข้าสู่ระบบ / ออกจากระบบ**: ล็อกอินด้วยชื่อผู้ใช้+รหัสผ่าน ได้โทเคนอายุ 12 ชม. กด "ออกจากระบบ" โทเคนจะถูกยกเลิกทันที ล็อกอินผิด 5 ครั้งต้องรอ 15 นาที
- **รีวิวเกม**: เพิ่มรีวิวใหม่, แก้ไข (ชื่อ หมวด เรตอายุ คะแนน วันที่ แพลตฟอร์ม รูปปก เนื้อรีวิว จุดเด่น/จุดด้อย) พร้อมพรีวิวการ์ด, ลบเกม (ลบยอดวิว/คอมเมนต์/ดาวของเกมนั้นด้วย)
- **ความคิดเห็น**: ดูคอมเมนต์ล่าสุดทุกเกม ค้นหา และลบสแปม

### ตั้งค่าบน Render > Environment
| ตัวแปร | ความหมาย |
|---|---|
| `ADMIN_USERNAME` | ชื่อผู้ใช้ (ไม่ตั้ง = `admin`) |
| `ADMIN_PASSWORD` | รหัสผ่าน **จำเป็น** — ถ้าไม่ตั้ง ระบบ admin จะปิด (ใช้รหัสยาว เดายาก) |
| `SESSION_SECRET` | ข้อความลับยาวๆ สำหรับเซ็นโทเคน (render.yaml สร้างให้อัตโนมัติ) ถ้าไม่ตั้ง ทุกครั้งที่เซิร์ฟเวอร์รีสตาร์ต/หลับต้องล็อกอินใหม่ |
| `SESSION_HOURS` | อายุการล็อกอิน (ชั่วโมง ค่าเริ่มต้น 12) |

### API ของ admin (ต้องส่ง header `Authorization: Bearer <token>`)
| Endpoint | ใช้ทำอะไร |
|---|---|
| `POST /api/admin/login` | `{username, password}` → `{token}` |
| `POST /api/admin/logout` | ยกเลิกโทเคน |
| `GET /api/admin/me` | เช็กว่ายังล็อกอินอยู่ |
| `GET/POST /api/admin/games` | รายการเกม / เพิ่มเกม |
| `PUT/DELETE /api/admin/games/:id` | แก้ไข / ลบเกม |
| `GET /api/admin/comments` | คอมเมนต์ล่าสุด (ลบด้วย `DELETE /api/comments/:id`) |

> **สำคัญ**: ถ้าไม่ได้ตั้ง `DATABASE_URL` เกมที่เพิ่ม/แก้ผ่าน admin จะเก็บใน `store.json` ซึ่ง **หายเมื่อ Render ฟรีรีสตาร์ต/deploy ใหม่** — ใช้งานจริงควรตั้ง `DATABASE_URL` (PostgreSQL/MySQL) ก่อน
> รูปปก: ใส่ลิงก์รูป `https://...` หรืออัปโหลดไฟล์ไว้ใน `frontend/images/` แล้วใส่ `images/ชื่อไฟล์.jpg`

### ทดลองในเครื่อง
```bash
cd backend && npm install
ADMIN_PASSWORD=รหัสของคุณ npm run dev        # Windows PowerShell: $env:ADMIN_PASSWORD="รหัสของคุณ"; npm run dev
cd frontend && npx serve . -l 5500           # เปิด http://localhost:5500/admin.html
```

## ระบบสมาชิก (สมัครสมาชิก / เข้าสู่ระบบ / ออกจากระบบ)
- ปุ่ม **เข้าสู่ระบบ** และ **สมัครสมาชิก** อยู่มุมขวาบนของหน้าเว็บ สมัครด้วยชื่อผู้ใช้ (a-z, 0-9, _ ยาว 3–20 ตัว) ชื่อที่แสดง และรหัสผ่าน (อย่างน้อย 8 ตัว) ล็อกอินค้างไว้ได้ 30 วัน
- **ความคิดเห็น**: ต้องเป็นสมาชิกก่อนถึงจะแสดงความคิดเห็นได้ ระบบใช้ชื่อจากบัญชีให้เอง และขึ้นป้าย "สมาชิก" ข้างชื่อ สมาชิกลบความคิดเห็นของตัวเองได้
  ถ้าต้องการให้คนทั่วไปที่ไม่ได้สมัครพิมพ์ชื่อแล้วแสดงความคิดเห็นได้เหมือนเดิม ให้ตั้ง `COMMENT_GUESTS=true` บน Render
- **หน้า admin > แท็บสมาชิก**: ดูรายชื่อสมาชิก ค้นหา และลบสมาชิก (ความคิดเห็นของสมาชิกคนนั้นถูกลบด้วย และล็อกอินเดิมของเขาใช้ไม่ได้ทันที)
- รหัสผ่านเก็บเป็น hash (scrypt + salt) ไม่มีใครเห็นรหัสจริง รวมถึง admin ล็อกอินผิด 5 ครั้งใน 15 นาทีต้องรอ สมัครได้ไม่เกิน 5 บัญชี/ชั่วโมง/IP
- ตาราง `users` และคอลัมน์ `comments.user_id` ถูกสร้างอัตโนมัติตอนเซิร์ฟเวอร์เริ่ม (ฐานข้อมูลเดิมก็เพิ่มให้เอง)

> **สำคัญ**: ถ้าไม่ได้ตั้ง `DATABASE_URL` บัญชีสมาชิกจะเก็บใน `store.json` ซึ่ง **หายเมื่อ Render ฟรีรีสตาร์ต** ใช้งานจริงต้องตั้งฐานข้อมูลก่อน

| Endpoint | ใช้ทำอะไร |
|---|---|
| `POST /api/auth/register` | `{username, name, password}` → `{token, user}` |
| `POST /api/auth/login` | `{username, password}` → `{token, user}` |
| `POST /api/auth/logout` | ยกเลิกโทเคน |
| `GET /api/auth/me` | ข้อมูลสมาชิกที่ล็อกอินอยู่ |
| `GET /api/admin/users` / `DELETE /api/admin/users/:id` | (admin) รายชื่อสมาชิก / ลบสมาชิก |

## ต้องเข้าสู่ระบบก่อนใช้เว็บ
- เปิดหน้าเว็บโดยยังไม่ได้ล็อกอิน จะถูกพาไปหน้า **เข้าสู่ระบบ** (`/login`) ทันที และมีหน้า **สมัครสมาชิก** (`/register`) แยกต่างหาก ล็อกอิน/สมัครเสร็จจะกลับไปหน้าที่ตั้งใจเปิดไว้ (เช่นลิงก์รีวิวเกมที่มีคนส่งมา)
- ฝั่งเซิร์ฟเวอร์ล็อกด้วย: API ดูเกม/คอมเมนต์/ให้ดาว ต้องส่งโทเคนสมาชิกหรือผู้ดูแลเท่านั้น (เปิดไว้เฉพาะ `/api/health`, สมัคร/ล็อกอิน และ admin)
- ผู้ดูแลที่ล็อกอินหน้า admin แล้ว กด "ดูหน้าเว็บ" ได้เลยโดยไม่ต้องสมัครสมาชิก (แต่แสดงความคิดเห็นไม่ได้)
- ถ้าอยากกลับไปให้ทุกคนดูได้โดยไม่ต้องล็อกอิน ตั้ง `REQUIRE_LOGIN=false` บน Render (หน้าเว็บยังพาไปหน้าล็อกอินอยู่ ต้องแก้ index.html ด้วย)

## ปุ่มดูราคา / ไปหน้าเว็บเกม
- ในหน้ารีวิวแต่ละเกมมีปุ่มใต้ "จุดเด่น/จุดด้อย" กดแล้วเปิดแท็บใหม่
- ใส่ลิงก์ได้ที่หน้า admin > แก้ไขรีวิว > ช่อง **ลิงก์ดูราคา / เว็บเกม** (เช่น `https://store.steampowered.com/app/1091500/Cyberpunk_2077/` หรือเว็บทางการของเกม)
- ชื่อปุ่มเปลี่ยนตามเว็บ: Steam, Epic Games Store, PlayStation Store, Xbox Store, Nintendo eShop, GOG, Google Play, App Store ฯลฯ จะขึ้นว่า "ดูราคาบน ..." เว็บอื่นขึ้นว่า "ไปหน้าเว็บเกม"
- ถ้ายังไม่ใส่ลิงก์ ปุ่มจะเป็น "ค้นหาราคาบน Steam" (ค้นชื่อเกมบน Steam ให้) เกมที่ไม่ได้ขายบน Steam เช่น Valorant, League of Legends, Fortnite, Roblox ควรใส่ลิงก์เว็บทางการแทน
- เก็บในคอลัมน์ `games.store_url` (ระบบเพิ่มคอลัมน์ให้เองตอนเซิร์ฟเวอร์เริ่ม)

## อัปโหลดรูปปกจากหน้า admin
- ในฟอร์มแก้ไขรีวิว กดปุ่ม **อัปโหลดรูป** หรือ**ลากไฟล์รูปมาวางบนภาพตัวอย่าง** แล้วกด **บันทึก**
- รองรับ JPG, PNG, WebP, GIF ระบบย่อรูปในเบราว์เซอร์ให้กว้างไม่เกิน 1280px ก่อนส่ง (รูป 2 MB เหลือราว 100 KB) GIF เก็บตามเดิมเพื่อให้ยังเคลื่อนไหว จำกัด 3 MB ต่อรูป
- รูปเก็บในตาราง `images` ของฐานข้อมูล (ไม่หายเมื่อ Render รีสตาร์ต) และเปิดดูได้ที่ `https://<render>/api/images/<id>` ช่องรูปปกจะเป็น `/api/images/<id>`
- เซิร์ฟเวอร์ตรวจชนิดไฟล์จากเนื้อไฟล์จริง ไม่รับ SVG/HTML ที่ปลอมนามสกุล

## โปรไฟล์สมาชิก
- กดรูปตัวเองมุมขวาบน หรือเปิด `/profile` เพื่อดูโปรไฟล์ตัวเอง กดชื่อคนในความคิดเห็นเพื่อดูโปรไฟล์คนอื่น (`/profile?u=ชื่อผู้ใช้`)
- หน้าโปรไฟล์ใช้ธีมเดียวกับหน้าแรก (ไฟล์ `frontend/site.css` ใช้ร่วมกันทั้งสองหน้า แก้สี/รูปแบบที่ไฟล์นี้ที่เดียว)
- **แก้ไขโปรไฟล์**: รูปโปรไฟล์ (ตัดเป็นสี่เหลี่ยมจัตุรัส 400px ในเบราว์เซอร์) หรือใช้ตัวอักษรแรกของชื่อ, รูปแบนเนอร์ หรือใช้สีของเว็บ, ชื่อที่แสดง, แนะนำตัว 160 ตัวอักษร, เกมโปรด 3 เกม (แสดงเป็นการ์ดแบบเดียวกับหน้าแรก) — เห็นตัวอย่างด้านบนหน้าต่างก่อนกดบันทึก
- เปลี่ยนชื่อ/รูปแล้ว ความคิดเห็นเก่าแสดงชื่อและรูปใหม่ตาม
- สมาชิกอัปโหลดรูปได้ไม่เกิน 10 รูป/ชั่วโมง เก็บในตาราง `images` เหมือนรูปปกเกม โปรไฟล์เก็บในคอลัมน์ `users.profile` (JSON, ระบบเพิ่มให้เองตอนเซิร์ฟเวอร์เริ่ม)

| Endpoint | ใช้ทำอะไร |
|---|---|
| `PUT /api/auth/profile` | แก้โปรไฟล์ตัวเอง `{name, bio, avatar, banner, accent, favs}` |
| `POST /api/auth/images` | สมาชิกอัปโหลดรูปโปรไฟล์/แบนเนอร์ |
| `GET /api/users/:username` | ดูโปรไฟล์ สถิติ ป้าย เกมโปรด และความคิดเห็นล่าสุด |

## ข่าวสารวงการเกม / ไอที / คอมพิวเตอร์ (กรองก่อนขึ้นเว็บ)
- เซิร์ฟเวอร์ดึงข่าวจาก RSS ของสำนักข่าวทุก 10 นาที (ปรับด้วย `NEWS_INTERVAL_MIN`, ปิดด้วย `NEWS_DISABLED=true`) — ค่าเริ่มต้นเป็นสำนักข่าวที่เชื่อถือได้: GamingDose, Blognone, IGN, GameSpot, Eurogamer, PC Gamer, The Verge, Ars Technica, Tom's Hardware, TechPowerUp (ลิงก์ข่าวต้องอยู่ในโดเมนของสำนักข่าวนั้น และโพสต์ดีลลดราคา/โฆษณาจะถูกกรองออก)
- ข่าวภาษาอังกฤษแปลเป็นไทยอัตโนมัติ (เก็บหัวข้อต้นฉบับไว้แสดงคู่กัน): ไม่ตั้งค่าอะไรจะใช้ Google Translate แบบฟรี, ตั้ง `ANTHROPIC_API_KEY` เพื่อใช้ Claude แปล (สำนวนดีกว่า มีค่าใช้จ่าย, เปลี่ยนรุ่นด้วย `TRANSLATE_MODEL`), ปิดด้วย `TRANSLATE_DISABLED=true`
- **กรอง 2 ชั้น**: (1) อัตโนมัติ — ตัดข่าวเก่ากว่า 3 วัน ข่าวซ้ำ (ลิงก์/หัวข้อเดียวกัน) และข่าวที่มีคำต้องห้าม → แท็บ "ถูกกรองอัตโนมัติ" (2) **ผู้ดูแลอนุมัติ** — ข่าวที่ผ่านชั้นแรกเข้าคิว "รอตรวจ" ต้องกดอนุมัติก่อนขึ้นเว็บ (เปิด "อนุมัติอัตโนมัติ" ให้แหล่งที่ไว้ใจได้)
- หน้า admin > แท็บ **ข่าวสาร**: อนุมัติ/ไม่อนุมัติทีละข่าวหรือเลือกหลายข่าว, เอาข่าวลงจากเว็บ, กู้ข่าวที่ถูกกรอง, ปุ่ม "ดึงข่าวตอนนี้", ตั้งค่าแหล่งข่าว (เพิ่ม/ลบ/ปิด, หมวด, ภาษา) และคำต้องห้าม
- หน้า `/news` แสดงข่าวที่อนุมัติแล้ว แยกหมวด เกม / ไอทีและดิจิทัล / ฮาร์ดแวร์คอมพิวเตอร์ เช็กข่าวใหม่ทุก 1 นาที (ขึ้นปุ่ม "มีข่าวใหม่") + กล่อง "ข่าวล่าสุด" บนหน้าแรก
- แสดงเฉพาะหัวข้อ สรุปสั้น (≤ 280 ตัวอักษร) รูป และลิงก์ไปต้นทาง ไม่คัดลอกบทความ ข่าวในระบบเก่ากว่า 30 วันถูกลบอัตโนมัติ เก็บในตาราง `news` และการตั้งค่าในตาราง `settings`
- หมายเหตุ: Render แพ็กเกจฟรีจะหลับเมื่อไม่มีคนใช้ ระหว่างหลับจะไม่ดึงข่าว พอมีคนเปิดเว็บก็กลับมาดึงต่อ
